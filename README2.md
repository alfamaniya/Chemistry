# README2 — شماره‌گذاری و توضیح اشیای صفحه اصلی

## هدف

این سند specification قابلیت جدید صفحه اصلی پروژه Chemistry است: **تمام اشیای قابل مشاهده و تمام ۱۱۸ عنصر جدول تناوبی باید شماره‌گذاری شوند و برای هر مورد توضیح مشخصی دربارهٔ ماهیت و کاربرد آن وجود داشته باشد.**

این سند فعلاً مرجع پیاده‌سازی است و تا زمان اجرای تغییرات، نباید به‌عنوان اعلام اجرای قابلیت تلقی شود.

## 1. اصول شماره‌گذاری

- شماره‌ها باید یکتا و قابل تشخیص باشند.
- شماره‌گذاری باید ترتیب منطقی نمایش صفحه را دنبال کند.
- با تغییر زبان فارسی/انگلیسی نباید از بین برود.
- برای عناصر، شمارهٔ نمایش‌داده‌شده باید دقیقاً همان `AtomicNumber` باشد.
- شمارهٔ عنصر نباید از index آرایه محاسبه شود.
- شماره‌ها باید در desktop، tablet، mobile، بلوک f و تمام Themeهای موجود حفظ شوند.

## 2. اشیای اصلی صفحه و توضیح آن‌ها

### 2.1 — Header

**توضیح:** سربرگ بالای سایت که هویت پروژه، ناوبری و انتخاب زبان را دربر می‌گیرد.

اشیای آن:

1. لوگو/هویت سایت — بازگشت به ابتدای صفحه.
2. نام سایت — نمایش عنوان پروژه.
3. شعار سایت — توضیح کوتاه هویت پروژه.
4. لینک جدول تناوبی — انتقال به جدول.
5. لینک سطوح آموزشی — انتقال به بخش سطوح.
6. لینک درباره — انتقال به بخش درباره/پایین صفحه.
7. کنترل فارسی — تغییر زبان رابط به فارسی.
8. کنترل English — تغییر زبان رابط به انگلیسی.

### 2.2 — Hero

**توضیح:** بخش معرفی اولیهٔ پروژه و مسیر ورود کاربر به جدول.

9. برچسب `CHEMISTRY • ELEMENTS` — معرفی حوزهٔ پروژه.
10. عنوان اصلی — معرفی مرجع شیمی و جدول تناوبی.
11. متن معرفی — توضیح کوتاه هدف سایت.
12. دکمه مشاهده جدول — انتقال کاربر به جدول تناوبی.

### 2.3 — جدول تناوبی

**توضیح:** هستهٔ اصلی رابط که ۱۱۸ عنصر را نمایش می‌دهد.

13. عنوان جدول — معرفی بخش جدول.
14. توضیح جدول — توضیح تکمیلی بخش.
15. کنترل Theme — انتخاب یکی از حالت‌های رنگی جدول.
16. توضیح Theme — راهنمای استفاده از کنترل رنگ‌بندی.
17. شبکه `periodic-table-grid` — محل ساخت کارت‌های عناصر.
18. بلوک `f-block` — محل نمایش لانتانیدها و اکتینیدها.
19. `table-status` — نمایش وضعیت بارگذاری/خطا/عملیات جدول.

### 2.4 — جزئیات عنصر

**توضیح:** بخشی که پس از انتخاب یک عنصر، اطلاعات آن عنصر را نمایش می‌دهد.

20. عنوان جزئیات — مشخص‌کنندهٔ بخش اطلاعات عنصر.
21. `selected-element` — کارت/محفظهٔ عنصر انتخاب‌شده.
22. سطح Beginner — اطلاعات آموزشی سطح مبتدی.
23. سطح Advanced — اطلاعات آموزشی سطح پیشرفته.
24. سطح Very Advanced — اطلاعات آموزشی سطح فوق‌پیشرفته.

شناسه‌های مهم فعلی که باید حفظ شوند مگر با اصلاح هماهنگ تمام وابستگی‌ها:

```text
periodic-table-grid
f-block
table-status
selected-element
beginner-info
advanced-info
very-advanced-info
```

## 3. شماره‌گذاری ۱۱۸ عنصر

**الزام:** هر ۱۱۸ عنصر باید شمارهٔ مشخص و قابل مشاهده داشته باشد.

شمارهٔ هر عنصر = `AtomicNumber`.

نمونه:

```text
1   — H   — Hydrogen / هیدروژن
2   — He  — Helium / هلیوم
6   — C   — Carbon / کربن
8   — O   — Oxygen / اکسیژن
26  — Fe  — Iron / آهن
79  — Au  — Gold / طلا
118 — Og  — Oganesson / اوگانسون
```

شماره باید در کارت عنصر و در جای ثابتی نمایش داده شود و با Symbol یا Name اشتباه نشود.

## 4. توضیح هر عنصر

هر کارت عنصر حداقل باید این اطلاعات قابل تشخیص را داشته باشد:

1. **Atomic Number** — شناسهٔ یکتای عنصر.
2. **Symbol** — نماد شیمیایی، مانند `H`، `He` و `Fe`.
3. **Name** — نام عنصر با پشتیبانی فارسی و انگلیسی.
4. **Detail** — اطلاعات عنصر که پس از انتخاب در بخش جزئیات نمایش داده می‌شود.

اطلاعات باید از داده‌های runtime گرفته شوند و نباید برای هر عنصر به‌صورت دستی در HTML تکرار شوند.

## 5. مدل شیء عنصر

هر عنصر یک شیء داده‌ای مستقل در نظر گرفته می‌شود:

```text
Element Object
├── AtomicNumber
├── Symbol
├── Name
├── Position / Group / Period
├── Classification
└── Detail Data
```

**توضیح:** این شیء نمایندهٔ یک عنصر واقعی در داده‌های پروژه است. UI باید دادهٔ همین شیء را نمایش دهد و از duplicate/hard-code کردن اطلاعات علمی جلوگیری شود.

## 6. منبع داده

منابع runtime فعلی باید حفظ شوند:

```text
data/PubChemElements_all.csv
data/ELEMENTS_118_ADVANCED.csv
data/ELEMENTS_118_VERY_ADVANCED.csv
```

کلید اتصال داده‌ها:

```text
AtomicNumber
```

هیچ شمارهٔ دستی یا جایگزین نباید ایجاد شود.

## 7. الزام JavaScript

منطق شماره‌گذاری باید در همان مسیر ساخت کارت عنصر قرار گیرد:

```text
Element data
    ↓
AtomicNumber
    ↓
Element card
    ├── Number
    ├── Symbol
    └── Name
```

برای مثال، عنصر آهن باید شمارهٔ `26` داشته باشد، حتی اگر ترتیب آرایه در آینده تغییر کند.

## 8. الزام CSS

برای شمارهٔ کارت عنصر یک selector مستقل مانند زیر در نظر گرفته شود:

```css
.element-number
```

این selector باید:

- در تمام Themeهای فعلی خوانا باشد؛
- با RTL/LTR سازگار باشد؛
- در mobile و desktop responsive باشد؛
- layout جدول را خراب نکند؛
- باعث ایجاد CSS تکراری یا بلااستفاده نشود.

## 9. Accessibility و UX

- شماره باید برای فناوری‌های کمکی نیز قابل تشخیص باشد.
- hover/focus نباید شماره را پنهان کند.
- شماره نباید روی Symbol یا Name قرار بگیرد.
- انتخاب عنصر با mouse، touch و keyboard باید حفظ شود.
- شماره در موبایل نیز خوانا باشد.

نمونهٔ مفهوم دسترسی‌پذیر:

```text
Element 26 — Fe — Iron
```

## 10. کنترل نهایی پس از پیاده‌سازی

- [ ] تمام ۱۱۸ عنصر شماره دارند.
- [ ] هر شماره دقیقاً برابر `AtomicNumber` همان عنصر است.
- [ ] شمارهٔ تکراری یا عنصر بدون شماره وجود ندارد.
- [ ] بلوک f نیز شماره‌گذاری صحیح دارد.
- [ ] شماره‌ها در فارسی و انگلیسی باقی می‌مانند.
- [ ] شماره‌ها در همهٔ Themeها باقی می‌مانند.
- [ ] desktop/mobile بررسی شده‌اند.
- [ ] انتخاب عنصر و بخش جزئیات همچنان کار می‌کند.
- [ ] CSVها بدون تغییر غیرضروری باقی می‌مانند.
- [ ] دادهٔ علمی جدید به‌صورت hard-code وارد HTML نشده است.
- [ ] تست‌های موجود پروژه پس از تغییر موفق هستند.

## 11. محدودیت تغییرات

این قابلیت نباید باعث بازطراحی غیرضروری پروژه شود.

> **کمترین تغییر ممکن در معماری فعلی، با حفظ رفتار موجود سایت و اضافه کردن شماره و توضیح به اشیای موجود.**

قبل از پیاده‌سازی باید وابستگی‌های `index.html`، `assets/js/main.js`، `assets/js/main-legacy.js`، `assets/css/main.css` و CSVهای runtime بررسی شوند.

پس از اجرای قابلیت، همین فایل باید بر اساس نتیجهٔ واقعی کد، تست و بازبینی نهایی به‌روزرسانی شود.
