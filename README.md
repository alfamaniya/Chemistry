# Chemistry — Periodic Table

پروژه آموزشی جدول تناوبی برای فارسی‌زبانان. این README وضعیت واقعی مخزن `main` را مستند می‌کند و فقط فایل‌ها و پوشه‌هایی را توضیح می‌دهد که در حال حاضر در مخزن وجود دارند.

## وضعیت فعلی مخزن

در وضعیت فعلی شاخه `main`، ریشه مخزن شامل این موارد است:

```text
.
├── README.md
└── data/
    ├── .gitkeep
    ├── PubChemElements_all.json
    └── elements/
        ├── .gitkeep
        └── ELEMENT_ATOMIC NUMBER_*.json
```

در حال حاضر فایل‌های رابط کاربری مانند `index.html`، فایل‌های CSS و JavaScript در شاخه `main` وجود ندارند؛ بنابراین README آن‌ها را به‌عنوان فایل موجود معرفی نمی‌کند.

## پوشه data/

`data/` محل داده‌های پروژه است و در حال حاضر شامل یک مجموعه داده کلی و یک پوشه اختصاصی برای فایل‌های هر عنصر است.

### `data/PubChemElements_all.json`

این فایل مجموعه داده کلی عناصر است. ساختار فعلی آن شامل فیلدهایی مانند موارد زیر است:

- `AtomicNumber`
- `Symbol`
- `Name`
- `AtomicMass`
- `CPKHexColor`
- `ElectronConfiguration`
- `Electronegativity`
- `AtomicRadius`
- `IonizationEnergy`
- `ElectronAffinity`
- `OxidationStates`
- `StandardState`
- `MeltingPoint`
- `BoilingPoint`
- `Density`
- `GroupBlock`

این داده در خود مخزن موجود است و منبع داده‌ای کلی برای عناصر محسوب می‌شود.

## `data/elements/`

این پوشه برای نگهداری **فایل اختصاصی هر یک از ۱۱۸ عنصر** ایجاد شده است.

نام فایل‌ها بر اساس شماره اتمی تنظیم شده است:

```text
ELEMENT_ATOMIC NUMBER_1.json
ELEMENT_ATOMIC NUMBER_2.json
ELEMENT_ATOMIC NUMBER_3.json
...
ELEMENT_ATOMIC NUMBER_118.json
```

فایل‌های این پوشه داده‌های اختصاصی عناصر را نگهداری می‌کنند. فایل‌های موجود از داده‌های PubChem PUG-View تهیه شده‌اند.

هر فایل مستقل از فایل عنصر دیگر است و شماره اتمی آن مشخص می‌کند که مربوط به کدام عنصر است.

## معماری موردنظر رابط کاربری

ساخت رابط جدول تناوبی در ادامه پروژه بر اساس تفکیک سه بخش انجام خواهد شد:

```text
HTML
 └── ساختار و بلوک‌های ۱۱۸ عنصر

CSS
 └── ظاهر، رنگ، اندازه و جانمایی اشیای رابط

Data
 └── اطلاعات عناصر
```

وقتی فایل‌های رابط کاربری دوباره به مخزن اضافه شوند، `index.html` باید فقط ساختار صفحه و بلوک‌های عناصر را نگهداری کند و اطلاعات علمی عناصر داخل HTML به‌صورت ثابت نوشته نشود.

اطلاعات هر کارت باید از فایل داده اختصاصی همان عنصر در `data/elements/` خوانده شود.

## اصل تفکیک فایل‌ها

برای جلوگیری از شلوغ شدن `index.html`، هر شیء یا بخش جدیدی که در HTML تعریف می‌شود باید ظاهر و قوانین بصری خودش را در فایل CSS متناسب با نام آن شیء داشته باشد.

به‌صورت کلی:

```text
HTML → ساختار
CSS  → ظاهر
DATA → اطلاعات
JS   → منطق و بارگذاری داده
```

این بخش معماری موردنظر پروژه است و تا زمانی که فایل‌های مربوطه در مخزن ایجاد نشده‌اند، نباید به‌عنوان فایل موجود تلقی شوند.

## قوانین نام‌گذاری

- نام فایل‌ها و پوشه‌های جدید باید به زبان انگلیسی باشد.
- برای هر عنصر، فایل داده اختصاصی خودش استفاده می‌شود.
- اطلاعات علمی نباید بدون نیاز در فایل ساختاری HTML تکرار شوند.
- ظاهر و داده باید از ساختار HTML جدا نگه داشته شوند.

## منبع داده

داده‌های موجود در `data/` بر پایه داده‌های PubChem هستند. فایل `PubChemElements_all.json` در مخزن فعلی موجود است و فایل‌های اختصاصی عناصر نیز در `data/elements/` نگهداری می‌شوند.

## کارهای بعدی

1. تکمیل و تثبیت ۱۱۸ فایل عنصر در `data/elements/`.
2. ایجاد مجدد `index.html` برای ساختار جدول ۱۱۸ عنصری.
3. ایجاد فایل‌های CSS مستقل برای بخش‌ها و اشیای رابط.
4. ایجاد JavaScript برای بارگذاری داده هر عنصر از فایل اختصاصی خودش.
5. اتصال ساختار، ظاهر و داده بدون انتقال اطلاعات علمی به HTML.
